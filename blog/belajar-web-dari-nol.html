Belajar web dari nol: urutan yang kami rasa masuk akal

10 November 2026 5 menit baca Tim DAFFTECH

Kalau kamu baru ingin belajar bikin website, layar pertama yang muncul biasanya penuh istilah: React, Tailwind, Next.js, build tool, paket manager. Semuanya terdengar penting, dan semuanya memang penting — nanti. Di awal, urutannya jauh lebih sederhana.

1. HTML — kerangka

HTML menentukan apa yang ada di halaman: judul, paragraf, gambar, tautan, tombol, form. Tidak ada HTML, tidak ada halaman. Mulai dari sini karena setiap teknologi web lain pada akhirnya menghasilkan HTML juga — browser hanya mengenal itu.

Yang perlu dikuasai di tahap ini cuma segelintir tag: heading, paragraf, daftar, gambar, tautan, dan form. Sisanya menyusul saat butuh.

2. CSS — tampilan

CSS menjawab pertanyaan "bagaimana ini terlihat": warna, ukuran huruf, jarak, posisi, responsif di layar kecil. Di tahap inilah kebanyakan orang merasa mulai "bisa desain" — dan juga di sinilah kebanyakan orang berhenti karena langsung melompat ke framework sebelum paham model dasarnya.

Dua konsep yang paling sering dipakai sehari-hari: flexbox untuk satu arah (baris atau kolom), dan grid untuk dua arah. Kuasai dua itu, 80% tata letak harian selesai.

3. JavaScript — perilaku

JavaScript membuat halaman bereaksi: menu terbuka, formulir memvalidasi diri, tombol mengganti isi. Mulai dari tiga konsep dulu — variabel, fungsi, dan event. Selebihnya (array, DOM, fetch) akan terasa perlu sendiri saat kamu punya proyek yang menginginkannya.

4. Baru kemudian: framework

React, Vue, dan kawan-kawan mempermudah proyek besar. Tetapi mereka tidak menggantikan ketiga hal di atas — mereka membungkusnya. Pernah melihat kode React yang kamu pahami? Di dalamnya tetap ada HTML (JSX), CSS, dan JavaScript biasa.

Aturan praktisnya: kalau kamu belum bisa membuat satu halaman lengkap tanpa framework, framework-nya belum waktunya. Halaman itu tidak harus cantik — harus jalan dulu.

Proyek pertama yang realistis

Bukan toko online, bukan aplikasi chat. Satu halaman: profil atau landing page sederhana dengan judul, beberapa paragraf, gambar, dan kontak. Selesai dalam beberapa hari, bisa dipublikasikan gratis lewat GitHub Pages, dan — yang paling penting — ada yang melihatnya. Reaksi orang asli lebih berguna daripada seratus tutorial.

Urutan inilah yang kami pakai saat menyusun e-book programming kami: pengenalan, HTML, CSS, JavaScript, proyek praktik, lalu cara menerbitkannya. Delapan bab, tanpa lompatan.
